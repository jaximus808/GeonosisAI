# Decisions made without Jaxon (with revert plans)

Format: decision · why · who decided · how to revert quickly.

- **SpacetimeDB on Maincloud (`robo-factory-a706j`), TypeScript module**: user-provided DB, TS is the recommended module language. Decided by: plan (Fable) + user. Revert: `spacetime start` locally, set `SPACETIME_HOST=http://localhost:3000` in `.env`, republish `spacetime/`.
- **Stripe: built on API keys + skills/docs, not the Stripe MCP planner**: MCP needed browser OAuth and the user was away. Revert: after OAuth, run `stripe_implementation_planner` and diff it against `docs/stripe-plan.md`.
- **Fly deploy deferred to morning**: no Fly secrets yet. Everything runs locally.
- **Eval ship rule compares the point estimate by default (`require_ci_low=false`); the Wilson 95% CI is always shown** (TDM-66): with 10 trials, the Wilson lower bound is at most 0.72, even at 10/10, so a CI-low rule can never clear a 0.8 target. Stats live in `services/orchestrator/src/rdf_orchestrator/stats.py` (stdlib only), not `services/common/`, because `services/common` (rdf-common) was not committed yet. The file is stdlib only, so it can move into `rdf_common` once that lands. Decided by: TDM-66 worker. Revert: set `require_ci_low=true` in run settings (to clear 0.8 you need at least 16/16, or about 63/70 at a 90% rate), or move the file to a shared package.
- **S-02 (TDM-7): Python services talk to SpacetimeDB with a small raw-WebSocket client (`v1.json.spacetimedb`) plus HTTP reducer calls, no TS sidecar**: no maintained Python SDK for 2.x exists (PyPI `spacetimedb-sdk` is 0.7 from 2023); maincloud accepts the JSON subprotocol and `spikes/tdm-7-spacetime/spike_spacetime.py` proves call → live insert, reconnect + resubscribe, and threaded use. Module language stays TypeScript. Decided by: TDM-7 worker. Revert: if a server upgrade drops `v1.json`, swap `StdbSubscriber` for a 1-s `sql()` poll on `id > last_id` (same callbacks), or run a ~30-line Node relay with the `spacetimedb` TS SDK that POSTs rows to the service.
- **TDM-2 env names: kept `SPACETIME_HOST`/`SPACETIME_DB_NAME`/`SPACETIME_TOKEN`, not the brief's `SPACETIMEDB_URI`/`_MODULE`/`_TOKEN`**: those names are already in `.env`, the worker guide and the SpacetimeDB docs. Non-secret wiring (`ORCHESTRATOR_URL`, `ROBOT_ID`, `JETSON_WS_PORT`) has code defaults, so it is never "missing"; `STORAGE_*` is only required by code that loads `StorageSettings`/`storageEnv`. Loaders read process env first, then repo-root `.env`. Decided by: TDM-2 worker. Revert: rename fields in `services/common/src/rdf_common/settings.py` and `packages/env/index.ts` plus `.env.example`.
- **Episode media lives on a Modal Volume (`rdf-media`) behind a small signed-URL endpoint on Modal (`services/media-store/`), not MinIO/Tigris/HF Hub** (TDM-4). Why: it is the only option tonight that every consumer can reach with the credentials we have. The Jetson at the office and the browser upload over public HTTPS (presigned PUT, CORS on, bodies up to 4 GiB); Modal training jobs mount the same Volume read-only at `/media` (no copy, no sync job); the dashboard plays clips from a presigned GET that supports Range requests; and it needs zero new secrets (Modal CLI is logged in; one self-generated HMAC key, `RDF_MEDIA_SIGNING_KEY`, shared between `.env` and a Modal Secret). Rejected: MinIO on the laptop (Modal and the office Jetson cannot reach it; needs a sync job plus a tunnel), Tigris (no Fly secrets until morning), HF Hub private repos (no signed URLs for private files, so the video player would need a proxy; commit-per-episode is slow; keep HF for publishing the per-ticket LeRobot dataset in E09, not as the raw blob store). Decided by: tdm4-storage-executor (Fable), user asleep. Revert/swap: the orchestrator only talks to `rdf_orchestrator.storage.get_backend()` (`signed_put` / `signed_get` / `list` / `put`), and every `storage_uri` is `<scheme>://<bucket>/<key>` with the same key layout `tickets/{ticket_id}/episodes/{episode_id}/{file}`. To move to Tigris/S3: set `RDF_MEDIA_BACKEND=s3` plus `STORAGE_ENDPOINT/BUCKET/ACCESS_KEY/SECRET_KEY` in `.env` (the `S3Backend` in the same file already presigns with boto3; unverified tonight), restart the orchestrator; old `modal-vol://` URIs keep resolving because `signed_get` dispatches on the URI scheme. To copy existing media across: `modal volume get rdf-media / ./dump && aws s3 sync ./dump s3://<bucket>/`. Modal training jobs then read via `CloudBucketMount` instead of the Volume (one-line change in the job's mounts).
- **TDM-8 published additively, without `--delete-data`**: when the schema was ready, `event_log` held 6 more `spike.tdm7` rows besides the 5 infra smoke rows, and the TDM-7 spike was live against the DB, so the "only smoke rows" condition for a one-time wipe no longer held. All 20 tables were added through a normal migration, and the owner was seeded into `service_identity` through `bootstrap_owner` (event 12). The one-time clean wipe is still unused. Decided by: TDM-8 worker. Revert or redo: once TDM-7 finishes and nothing real has landed, the coordinator may run one `spacetime publish -s maincloud robo-factory-a706j --delete-data=always --yes=remote,migrate`. `init` then re-seeds the owner, so `bootstrap_owner` isn't needed.
- **SpacetimeDB enums are strings, and FK sentinel 0 means "none"**: strings keep the HTTP/JSON API simple for Python, and option columns can't be index-filtered from clients. Allowed values are in `spacetime/spacetimedb/src/enums.ts`. Decided by: TDM-8 worker. Revert: change the columns to `t.enum`/`t.option`, which needs a breaking migration.
- **TDM-10 claim lease TTL depends on task type: 60 s for arm control (`clean_teleop`, `recovery_takeover`), 10 min for `reset`. The brief said 10 min for every task.** Why: the lease is the arm-control lock, and TDM-57 needs a dead tab or phone to lose control within 60 s (it heartbeats every 30 s). A 10-minute lease would lock the arm for 10 minutes after a disconnect. Also: at most one live arm-control lease per robot, an expired lease is never revived (the holder must claim again and can lose to someone else), and expiry is enforced lazily inside every reducer, so the lock never depends on the `expire_task_leases` sweeper running. Decided by: TDM-10 worker. Revert: set `CONTROL_LEASE_MICROS` in `spacetime/spacetimedb/src/reducers/marketplace.ts` to `TASK_LEASE_MICROS` and republish.
- **TDM-13 added `robot_command.seq` (per-robot command sequence, `u64` default 0) and published it with `--yes=break-clients`**: the operator asked for sequenced, acked commands, and auto-inc ids have gaps (SpacetimeDB says not to order by them; the local test showed id 9 with seq 8). Adding a column at the end of a table counts as a client-breaking migration, so connected clients were dropped once and had to reconnect. No data was lost: the table was empty. Also added enum values `starting`/`resuming` (agent), `resume_policy`/`home`/`soft_estop` and status `preempted` (robot commands). Decided by: TDM-13 worker. Revert: drop the column from `schema.ts` (this is breaking and needs `--delete-data=on-conflict`), or ignore `seq` and order by `issued_at`.
- **TDM-11 owns `approve_spend`, and the payout budget guard has two caps.** No E02 brief named `approve_spend` (TDM-12's file defers it to "another ticket"), so it sits in `reducers/episodes_payments.ts` next to the guard that reads `approved_cents`. Every reservation checks `ticket.spent_cents + amount <= ticket.budget_cents`. A payout for a task tied to a data plan also needs `(that plan's reserved payouts) + amount <= data_plan.approved_cents`. Resets and dataset batches are capped by budget only, because baseline resets run before any plan exists and TDM-12 allows only clean/recovery plans. A payout over a cap is still written, as `blocked_budget` (with the reason in `error`) and without touching spend, and `reserve_payment` re-reserves it once budget or approval rises. `spent_cents` counts pending, awaiting_onboarding and paid rows; `failed` and `reversed` release their amount. Decided by: TDM-11 worker. Revert: change `tdm11Reserve` in that file, or move `approve_spend` elsewhere (keep the reducer name, because TDM-80/TDM-64 call it).
- **TDM-3 compose: MinIO image `pgsty/minio`, local SpacetimeDB on host port 3300**: the official `minio/minio` image is gone from Docker Hub, and port 3000 is taken on this laptop. Decided by: TDM-3 worker. Revert: change the image or port in `docker-compose.yml` (the `minio` / `local-spacetime` profiles); nothing in the apps depends on either.
- **TDM-20 added `run_settings.data_type_override` (string, default `''`) and taught `update_run_settings` the key**: the run-settings API brief lets a human force the planner's data type, and the reducer is the source of truth, so the value needs a column it can validate (`null`/`''` = the planner decides, else `clean_teleop`|`recovery_takeover`). `create_ticket` overrides accept it too. Adding a column needs `--yes=break-clients` (connected clients drop once). Status: tested on a local server; the TDM-20 worker's own maincloud publish was refused by its permission check, but a later shared-tree publish by another worker carried the column, and the live test passed on maincloud (test robot `test.tdm20-bot` id 2, ticket 2, cancelled). Decided by: TDM-20 worker. Revert: drop the column line in `schema.ts` and the `data_type_override` case in `reducers/tickets.ts` (dropping the column is breaking and needs `--delete-data=on-conflict`); the API field can be removed from `run_settings_api.py`.
- **TDM-15 made `append_event` service-only and routed every event_log write through `logEvent` (`spacetime/spacetimedb/src/event_log.ts`).** Why: event_log is the evidence for "what ran on its own", so anonymous callers must not be able to write to it, and one insert site makes "no update or delete path" checkable (`python3 -I scripts/verify_event_log.py static`). `append_event` also refuses malformed actor/type values, invalid JSON, and a non-owner logging as another service role. The actor convention is documented but not enforced, so existing actors keep working. Anonymous scripts must now use `SPACETIME_TOKEN` or a registered service identity. Decided by: TDM-15 worker. Revert: drop the `requireService` line (and the checks) from `append_event` in `src/index.ts` and republish.
- **Factory Droids run locally via droid-sdk tonight, cloud after the GitHub push**: S-04 proved native resume on both local and cloud, but cloud Droid Computers can't reach this repo without a git remote, and the user is asleep. Decided by: orchestrator session. Revert/switch: push the repo, add it to the Factory Environment, then set the factory client's mode to cloud. Session ids are kept in `agent_session.factory_session_ids_json` either way.
- **TDM-47 cameras: pip `opencv-python-headless` (V4L2, MJPG 640x480@30), camera names `top`/`wrist`, sync = nearest frame to each `top` frame within 20 ms.** The pip wheel installs everywhere with `uv sync` but has no GStreamer, so Jetson HW JPEG decode is opt-in via the system OpenCV. Names match the S-05a LeRobot keys (`observation.images.top/wrist`). Timestamps are CLOCK_MONOTONIC ns (V4L2 driver stamp when plausible), so robot state stamped with `time.monotonic_ns()` lines up. Out-of-sync samples are published with `in_sync=False` for the recorder to decide. Decided by: TDM-47 worker. Revert: `reference`/`pair_tolerance_ms` in `services/robot-client/config/cameras.yaml`; for GStreamer, `source: gstreamer` + a pipeline (example in the same file) on a venv with system site-packages.
- **TDM-17 `make seed` (`scripts/seed.py`) is local-only and seeds no results**: it creates robot `test.seed-yam-office-1` (yam_7dof, wrist + exo cams, camera_config `{"fake": true, "seed": true}`), contributor `test.seed-contributor` (left offline) and one `test.seed [SEED] ...` ticket with default run_settings, plus one `test.seed.applied` event; idempotent by name/robot. It writes no eval runs, trials, episodes, reviews, plans or payments, so nothing seeded can read as a real result, and the `test.` prefixes make /events and the ticket page label every row as test/FAKE. Maincloud is refused unless `--allow-maincloud --confirm-db <db>` (its event_log is the real-run evidence); other remote hosts need `--allow-remote`; `.env` SPACETIME_HOST/TOKEN are ignored. Decided by: TDM-17 worker. Revert: `make seed` back to the echo stub and delete `scripts/seed.py`; seeded rows on a local DB go away with its data dir.
- **TDM-80 Claude connector (`apps/mcp`): stateless Streamable HTTP at `POST /mcp`, bearer `MCP_TOKEN`; plan approvals call the `approve_spend` reducer directly as the connector's own SpacetimeDB identity.** Why: the orchestrator has no approve-spend route, the reducer already allow-lists the `mcp` role and caps total approvals at the ticket budget, and the token stays on the server. Every action is logged as `human:via_mcp` (reducer `approved_by`, or `X-Human-Id: via_mcp` on `PATCH /tickets/{id}/settings` for budget raises). The connector requires an explicit amount in cents (no "0 = use the estimate") and caps one call at `MCP_MAX_SPEND_CENTS` (default $500). Before the real run, set `SPACETIME_TOKEN` for the mcp container to a registered `mcp` identity (`POST /v1/identity` + `register_service_identity(..., "mcp", ...)`), not the owner token. Claude.ai custom connectors cannot send a static bearer header, so the remote deploy needs OAuth or another scheme (TDM-81). Decided by: TDM-80 worker. Revert: route approvals through a new orchestrator endpoint and swap `SpacetimeHttp.callReducer` in `apps/mcp/src/tools.ts` for it.
